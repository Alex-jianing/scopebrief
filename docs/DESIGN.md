# 问据界面设计

问据面向需要跨项目核对规范、变更和决策的团队。一次问答从选项目和输入问题开始，经由结论和引用回到文档当时的版本与原文行号。

## 从成熟产品学到的做法

| 参考产品 | 公开资料里的做法 | 在问据中的应用 |
| --- | --- | --- |
| Linear | 降低侧栏和分隔线的视觉重量，让用户在不同页面找到位置一致的操作。用 `/` 打开搜索。 | 左栏收纳导航、历史和账号，浅色界面突出当前任务。按 `/` 聚焦提问框。 [界面更新](https://linear.app/now/behind-the-latest-design-refresh) · [搜索快捷键](https://linear.app/docs/search) |
| Raycast | 从一个输入框开始，常用动作支持键盘操作。 | 首页集中展示问题和项目范围，用 Ctrl/⌘＋Enter 提交。演示问题紧接提问框，点击即可运行。 [Search Bar](https://manual.raycast.com/search-bar) |
| Google Gemini Notebook | 用户可以选择本次问答使用的资料，选择引用后直接查看原文上下文。 | 提交前确认项目范围，提交后显示证据与轨迹。点击引文打开具体版本，自动定位并高亮原文。 [问答与引用](https://support.google.com/gemininotebook/answer/16179559?hl=en) |
| Apple 排版指南 | 用字号、字重和颜色表达信息层级，在不同屏幕尺寸检查可读性。 | 提问和段落正文用易读的常规字重，页面标题用半粗字重，时间、行号和版本编号形成稳定的辅助层。 [Typography](https://developer.apple.com/design/human-interface-guidelines/typography) |

“问据”将提问和依据合成一个易读的短名，发音与“问句”相同。产品副标题用“团队知识工作台”交代使用场景。短名用于导航、登录和浏览器标题，让同一产品在不同页面易于识别。 [Linear 品牌命名](https://linear.app/brand)

## 页面与交互

- **提问**。项目范围和提交键在一个表单内，所选项目会留在按钮上。历史问题可从左栏回看，当前结果标出上次运行使用的项目范围。
- **阅读**。桌面左侧读结论、右侧核对证据。窄屏按结论、证据、继续提问的顺序排列，回答标题下方可以直接跳到证据。
- **管理**。资料库、评测和团队管理使用同一套标题、筛选、表格和反馈样式。资料筛选时显示结果数量。
- **反馈**。排队、检索、取消、证据不足和加载失败都有实际状态。切页、资料抽屉和范围菜单使用约 150–250 ms 的过渡，支持系统的减少动效设置。

## 排版和视觉规则

| 元素 | 设置 |
| --- | --- |
| 字体 | 英文与数字用 Inter，简体中文用械黑 GB，行号和技术标识用 Geist Mono，较少见的汉字逐级回退。 |
| 标题 | 工作台主标题桌面约 31–50 px，手机约 27–34 px。模块标题和问题标题用半粗字重。 |
| 正文和辅助信息 | 证据正文 15 px、1.75 倍行高，提问输入 16 px，操作和辅助文字多为 13 px 和 12 px。 |
| 间距 | 基准间距 8、12、16、24、32 px。表单的范围和提交键靠近，跨模块用更宽的留白。 |
| 色彩与表面 | 浅底承载阅读，低饱和绿区分导航与内容，深绿留给主操作。版本、状态和失败同时有文字标签。 |
